# STM32F4 Demo

This project is a demonstration of the integration of Scrutiny on a STM32F411 Discovery board in C using the C Wrapper.
It uses CMake, builds with ARM GCC and comes with all required STM32-specific build dependencies.

The application reads the onboard accelerometer and IOs and expose the values in a global variables. Aliases are added on top of them, making them available through Scrutiny with friendly path like ``/IMY/Accel_X (G)``

The communication is handled through a USB virtual serial port (CDC-ACM) exposed on the user USB connector using the ST libraries. This type of virtual serial port runs at 1Mbits/sec regardless of the Serial configuration done on the host machine. Such speed and the low latency of the CDC driver allow the Scrutiny server to poll the device at a rather high rate. 

To ease the integration with CMake, all files auto-generated by CubeMX IDE have been put under the ``stm32cubemx`` folder and are loaded in a single CMake object library file.

## Timings

TIM2 runs at 1MHz and is used as a time reference for Scrutiny with microsecond precision. 
``HAL_GetTick()`` could be used instead, but because of its millisecond precision, embedded graphs taken with the idle loop would have a very coarse time precision.

TIM3 is used to generate a 1KHz interrupt that runs a loop handler, enabling low-jitter embedded graphs.

The main idle loop runs at ~300Hz because reading the accelerometer is a blocking task that takes about 3.2ms.

## Required hardware

- [STM32F411 Discovery board](https://www.st.com/en/evaluation-tools/32f411ediscovery.html)
- 2x USB Cable  (Power & Communication)

## Required software

- GCC for ARM32
- CMake
- \[Optional\]: GNU Make
- \[Optional\]: Bash (Git bash for Widnows is fine)

## Prebuilt binary

The prebuilt binary (ready to be flashed) and the Scrutiny Firmware File (.sfd) to be loaded onto the server can be found in ``./prebuilt``

## Building

For CMake 3.25+
```bash
cmake --preset Release
cmake --build build/Release --parallel $(nproc)
```
Or, use the following bash build script 

```bash
./scripts/build.sh
```

Once built, the binary `build/Release/stm32_demo_tagged.[hex|elf]` can be falshed onto the device using a tool like [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)
